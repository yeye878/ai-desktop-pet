## 一、先量化参考图

你的图我用 PIL 逐像素测了（1392×604）：

| 指标 | 你的参考图 | 我改之前 |
| --- | --- | --- |
| avgL（平均亮度） | **0.955** | 0.925 |
| 纯白 `#ffffff` 占比 | **63.4%** | 0 |
| avgC（平均彩度） | 0.021 | 0.014 |
| 鲜艳像素（C>0.08） | 12.0% | — |
| 暗部（L<0.5）占比 | 0.4% | — |

关键发现：**你的图是「63% 纯白 + 一条 85px 高的高饱和彩虹带」**。
彩虹带的实测颜色：

| 色相 | 实测色 | 彩度 C |
| --- | --- | --- |
| 青 | `#07b6ce` / `#49c0cc` | 0.106~0.123 |
| 橙红 | `#f66325` / `#f04642` | 0.190~0.207 |
| 绿 | `#20c463` | 0.187 |
| 紫 | `#ac54f2` / `#bf50d7` | 0.215~0.230 |

而我改之前：纸面是奶油米白（`#f6f3eb`，彩度 0.020）、强调色只有 C 0.082。
**所以"灰暗"的根因不是我亮度调低了，是纸面不白 + 强调色不够饱和。**

## 二、配色改动

### 纸面：奶油米白 → 接近纯白

```
改前  sand-100 = L 0.962 / C 0.020   → #f7f3eb（偏黄发闷）
现在  sand-100 = L 0.988 / C 0.002   → #fcfbfa（接近纯白，只留一丝温度）
```

### 强调色：彩度 0.082 → 0.117

```
改前  celadon-600 = L 0.660 / C 0.082   → 青得发灰
现在  celadon-600 = L 0.691 / C 0.117   → #04b1b7，参考图量级
```

### 拆成四个角色（这才是"既亮又能读"的解法）

之前反复在「亮」和「可读」之间摆，是因为把两个角色塞进一个颜色。现在分开：

| 令牌 | 色值 | 用途 | 对比度 |
| --- | --- | --- | --- |
| `accent` | `#04b1b7` | 色块、选中态、图标 | 白纸 2.55:1（图形足够） |
| `onAccent` | `#24201d` | 压 accent 上的文字 | **7.0:1** |
| `accentStrong` | `#148286` | 需要白字的实心按钮 | 白字 **4.60:1** |
| `accentText` | `#20787c` | kicker / 标签小字 | 白纸 **5.03:1** |

12 套主题全部按此重算，`primary` 彩度从 0.080 提到 0.117，
`bubbleUser` 保证白字 ≥4.56:1。

## 三、找到并修掉的三个"灰"源头

改纸面 token 后实测整窗 avgL 只从 0.820 升到 0.835 —— 说明还有别的东西在压暗。
逐个排查出三处：

### 1. 页面专属背景规则覆盖了基础规则

`.dashboard-content.page-appearance` 等 7 条规则的优先级高于 `.dashboard-content`，
我前面改基础规则**完全没生效**。这些规则里还留着旧配色的粉紫渐变
（`rgba(194,156,173,0.18)`）。已全部重写为白底 + 极淡主色光晕。

### 2. 「product polish layer」覆盖层

文件后段 L5322 处的 `.dashboard-root` / `.dashboard-sidebar` 覆盖规则，
用 `linear-gradient(paper-100 → paper-200)` 三层叠加，且
`background-blend-mode: multiply` 把侧栏压成灰绿（实测侧栏 avgL 只有 0.714）。
已改成 `soft-light` + 白色渐变。

### 3. 纹理层用 multiply

`paper-grain` 纹理用 `multiply` 混合会整体压暗。改成 `soft-light` 后只保留肌理。

## 四、一个副作用与修复

改侧栏时我把第一个色标写死成了 `rgba(255,255,255,.97)`，
结果 12 套主题的侧栏长得一模一样 —— `theme-probe` 直接报
「有主题侧栏底色重复，说明没真正跟随主题」。
已改回用 `--paper-tint-50-rgb` / `--paper-tint-150-rgb` 主题派生变量。
