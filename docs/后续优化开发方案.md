# 鸿蒙智伴（OpenCompanion）后续优化开发方案

> 阶段：主体功能鸿蒙迁移完成后 → 参赛版本打磨
> 依据：《产业命题：OpenHarmony Agent 鸿蒙原生智能多模态个人助理》答题要求 ×《鸿蒙智伴—解决方案》承诺 × 迁移后现状盘点
> 日期：2026-09-06

## 一、现状盘点（迁移完成基线）

以 `OpenCompanion/`（ArkTS + ArkUI，API 20 / HarmonyOS 6.0）为基线，hvigor 编译通过、模拟器端到端验证通过（见 README-HarmonyOS.md）。命题要求覆盖现状：

| 命题要求 | 现状 | 差距（本方案要补） |
|---------|------|------------------|
| F1 多模态：语音/文本/图像 + 复合指令 | 三输入已通；图像走"选图后自动填默认文案" | **缺真正的复合指令解析引擎**（意图分类→子任务拆解→依赖路由），复合指令实际仍按单条消息进 LLM |
| F2 端侧 RAG 知识库 | RagBridge(RAG 会话) + 倒排索引 + 本地降级链 + 离线端侧模型 | 检索单通道（Kit 可用则不用本地）；**无会话预热**（冷会话首字时延高）；引用无文档定位 |
| F3 跨设备协同 | onContinue 接续（continuable） | **接续只带时间戳占位文本**，无真实会话上下文；无多端数据同步 |
| F4 ≥3 子智能体编排 | /team 规划→并行→综合；工坊；自进化 | **无超时/重试**（单成员挂起会拖死整队）；阶段轨迹不直观 |
| R3 手机+平板 | 断点布局（≥720vp 侧栏） | 宽屏下知识库/智能体页仍单栏堆叠（可接受，低优先级） |
| R4 冷启动≤3s / 语音≤2s | 启动纪律良好；ASR/TTS 预热 | **无量化埋点**（无法给验收数据）；TTS 整段回答完成后才播（违反"首字优先"承诺）；无打断 |
| R5 语音识别精准度 | 静态热词表 | 热词**不随知识库/智能体动态更新**；无误识纠偏；无低置信度复述确认 |
| 方案承诺功能 | 日程管家有系统提醒工具 | **早间简报、遗忘曲线复习排期**（方案 4.5/场景三承诺）未落地 |

## 二、本阶段目标

1. 命题四大能力的"最后一公里"补齐：复合指令引擎化、RAG 多路召回与预热、接续带真实上下文、编排工程化；
2. 两条性能指标从"有手段"升级为"有数据"：冷启动/语音全链路埋点 + 首页自检可视化；
3. 语音精准度三件套：动态热词、指令词表纠偏、低置信度复述确认；
4. 继续开发"个人专业助理"差异化功能：早间简报、遗忘曲线复习计划（学习+日程智能体协作的确定性工具）；
5. 工程修缮与验收交付：构建回归、模拟器端到端走查、验收报告、git 提交。

## 三、工作项分解

### P0-1 复合指令解析引擎 `core/IntentEngine.ets`（对应命题 1、方案 4.1.1）
- 端侧规则式意图分类（毫秒级，不依赖 LLM）：高频指令短语表（打开知识库/新对话/今天日程/停止播报/现在几点/帮助/知识库状态…）；
- 编辑距离 ≤2 的**指令词表纠偏**（"打开支识库"→"打开知识库"），命中即本地直答，不走 LLM（语音响应 <500ms 的关键路径）；
- **复合指令拆解**：按触发模式把一句话拆为带依赖关系的子任务序列（拍文档→总结；总结→入库；查日程→排复习计划；拍照→OCR→提问），输出结构化子任务图；
- `ChatService.send` 接入：意图路由优先于 LLM（本地直答动作执行器：页面跳转/工具直调/状态汇报）；
- 未命中复合模式则维持现有单消息链路，行为完全向后兼容。

### P0-2 语音全链路流式播报与打断（对应方案 7.2"首字优先"）
- `ChatService`：开启自动播报时，流式 `onContent` 按句缓冲，**首个完整句即刻 TTS 播报**，边生成边合成边播放；
- 打断：播报中点击麦克风 → `TtsController.stop()` + 立即进入聆听（用户可随时打断）；
- 时延埋点：断句判定 → 首个语义反馈（直答文本或流式首字）打点。

### P0-3 语音识别精准度三件套（对应命题 5、方案第六章）
- **动态热词**：设置热词 ∪ 内置智能体名 ∪ 知识库文档标题（截断上限），ASR 引擎启动/知识库变更后重建；
- **指令纠偏**：识别结果先经 IntentEngine 词表对齐（编辑距离）再路由；
- **低置信度复述确认**：识别文本过短或纠偏分值低时，语音浮层展示"你是指：X？"（确认发送 / 重新说），杜绝错误指令静默执行。

### P0-4 知识库检索增强（对应命题 2、方案 4.2）
- **多路召回 RRF 融合**：Kit 倒排通道与本地 bigram 通道并行检索，倒数排名融合（RRF）重排去重——任一通道空结果不再直接放弃；
- **RAG 会话池预热**：首帧后 idle 预创建 RagSession（Kit 可用设备），降低冷会话首字时延；
- 引用来源增强：KbHit 携带文档 id，回答引用可对应到具体文档。

### P0-5 多智能体编排工程化（对应命题 4、方案 4.4）
- 子任务执行 **90s 超时 + 失败重试 1 次**（级联取消已有，单成员异常不拖垮团队升级为"不拖垮也不挂死"）；
- 阶段轨迹带时间戳与阶段标识（规划/派发/执行/汇总），执行全程可视更直观；
- 规划结果落盘到消息轨迹，便于答辩展示"自主分解"过程。

### P0-6 跨设备协同增强（对应命题 3、方案 4.3）
- `onContinue` 携带**真实会话上下文**：最近 6 条对话（角色+内容摘要）+ 来源页 + 桌宠状态，对端恢复进 ChatService 并提示"已从设备接力"；
- 新增 `commons/DistributedSync.ets`：distributedKVStore 分布式 KV（能力检测 + 惰性初始化 + 失败静默降级单端），同步"最新会话摘要 + 长期记忆增量"，任何一端提问拥有完整上下文；
- 组网自检：设置页显示分布式同步可用状态。

### P1-7 性能埋点与自检（对应命题 4 性能指标）
- `commons/PerfTrace.ets`：mark/measure 工具（hilog + 内存）；
- 冷启动三打点：abilityCreated → firstFrame → interactive，首页状态卡显示"冷启动 X.Xs（目标≤3s）"；
- 语音链路打点：断句→首反馈耗时，/perf 命令与首页可见。

### P1-8 个人助理能力继续开发（对应方案 4.5、场景三）
- **早间简报**：`/brief` 命令 + 日程管家技能——时间 + 天气 + 今日待办本地拼装（无 LLM 也可用）；
- **遗忘曲线复习计划**：新增 `create_review_plan` 工具——依据知识库文档标题生成 D+1/2/4/7/15 复习提醒（确定性落 create_reminder 系统通知），学习助手智能体白名单接入；
- 文档处理智能体新增 `summarize_doc` 确定性摘要工具（检索 Top-K + LLM 可选），复合指令"总结重点"可直连。

### P1-9 工程修缮
- `decodeWithStream` → `decodeToString`（弃用告警清零）；
- 语音浮层/输入区键盘避让核查（`expandSafeArea` 底部安全区）；
- 构建告警清理与 README 更新。

## 四、实施顺序与验收

| 步骤 | 内容 | 验收方式 |
|-----|------|---------|
| 1 | PerfTrace 埋点基座 | 构建 + 首页显示启动耗时 |
| 2 | IntentEngine + 本地直答 + ChatService 接入 | 模拟器输入"打开知识库/今天日程/几点"本地直答；"拍一下这个文档帮我总结重点"输出子任务轨迹 |
| 3 | 流式 TTS + 打断 | 自动播报开启后首句先于全文出现；播报中点麦克风可打断 |
| 4 | 动态热词 + 纠偏 + 复述确认 | 误识短语命中纠偏；低分文本弹复述确认 |
| 5 | KB RRF + RAG 预热 | 检索结果融合日志；二次提问首字时延下降 |
| 6 | 编排超时/重试/阶段轨迹 | /team 轨迹含阶段与耗时 |
| 7 | 接续真实上下文 + DistributedSync | wantParam 含会话摘要；设置页显示同步状态 |
| 8 | 简报 + 复习计划 + 摘要工具 | /brief 输出三段简报；create_review_plan 生成系统提醒 |
| 9 | 工程修缮 | 构建无弃用告警 |
| 10 | 全量构建 + 模拟器端到端走查 + 验收报告 + git 提交 | hvigor BUILD SUCCESSFUL；五页渲染 + 核心链路回归通过 |

## 五、风险与对策

| 风险 | 对策 |
|-----|------|
| distributedKVStore 在模拟器不可用 | 惰性 import + try/catch + 单端降级（与 RagBridge 同款防御模式，杜绝启动崩溃） |
| 模拟器无麦克风，语音链路无法实测 | 以单元化路径（词表纠偏纯函数）+ 日志埋点验证，真机项列入验收报告"待真机回归" |
| IntentEngine 规则误拦截正常消息 | 直答仅命中高置信短语（编辑距离≤2 且长度≥4），其余全部走原链路；可用 /命令直通 |
| 流式 TTS 与确认门/工具调用交织 | 播报缓冲仅在纯内容 delta 时推进，工具/确认帧自动 flush 并跳过播报 |
| 工期 | 全部为增量改造，不动已有主链路结构；每步 hvigor 回归 |
