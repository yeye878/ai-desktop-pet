# 「处理文档」在模拟器上失败 —— 出错点定位文档

> 仅定位，未改动任何业务代码。日期：2025-（见 git log）。
> 模拟器关键背景：x86 模拟器**裁剪了多个 AI 原生模块**（此前已确认 `data.retrieval` 被裁，见
> `RagBridge.ets:19-22` 的注释），OCR 所属的 CoreVisionKit 极大概率同样被裁剪。

## 一、「处理文档」涉及的三条链路

| 链路 | 入口 | 关键路径 |
|---|---|---|
| A. 知识库导入文本文档 | 知识库页「导入文档」按钮 | `KnowledgePage.ets:191` → `DocImporter.importTextDocs()`（DocumentViewPicker → fs 读取 → `KbService.ingest`） |
| B. 知识库拍照识字入库 | 知识库页「拍照识字」按钮 | `KnowledgePage.ets:199` → `DocImporter.importImagesOcr()`（PhotoViewPicker → **OCR** → `KbService.ingest`） |
| C. 对话复合指令「拍一下这个文档，帮我总结重点」 | 对话页相机按钮 / 语音 | `ChatService.send()` → `IntentEngine.parseComposite` → `runCompositePlan`（**OCR** → LLM 总结 [→ 入库]） |

## 二、出错点标记（按嫌疑度排序）

### 🔴 P0：OCR 能力在模拟器上缺失，且异常被静默吞掉（最可能的根因）

**位置：`entry/src/main/ets/knowledge/DocImporter.ets:80-104`（`ocrText`）**

```ts
try {
  await textRecognition.init();
} catch (e) {
  // 已初始化会抛重复初始化，忽略   ← 问题：这里吞掉的是「所有」异常
}
...
const result = await textRecognition.recognizeText(visionInfo);  // 模拟器上此处抛错
```

- `textRecognition`（CoreVisionKit）依赖设备原生 OCR 模块，模拟器通常不支持；
  全工程**没有任何 `canIUse('SystemCapability.AI.Vision.OCR')` 能力检测**。
- `init()` 的 catch 注释假设异常只会是"重复初始化"，实际上**模块不存在**也会在这里被静默吞掉，
  真正报错延迟到 `recognizeText` 才抛出。
- 对链路 B 的后果：`importImagesOcr` 里只 `Log.warn('ocr failed: ...')`（`DocImporter.ets:67`），
  用户只看到一句「未能从图片中识别出文字」，无任何原因提示。
- 对链路 C 的后果：`ChatService.ets:324-343`，每张图 OCR 失败只写一条轨迹
  `⚠️ 一张图片识别失败`，OCR 全文 <10 字后**降级为视觉 LLM**（`runSingle`）——
  如果此时图片没带上（见 P2）或配置的模型不支持视觉，就表现为"答非所问 / 处理不了文档"。

**验证**：hilog 过滤 `OpenCompanion`，找 `ocr failed:` 或消息轨迹里的 `⚠️ 一张图片识别失败`。

---

### 🔴 P1：页面层 Promise 没有 `.catch`，picker 一抛错就「点了没反应」

**位置：**

- `entry/src/main/ets/pages/KnowledgePage.ets:191-196`（导入文档）
- `entry/src/main/ets/pages/KnowledgePage.ets:199-203`（拍照识字）
- `entry/src/main/ets/pages/ChatPage.ets:200-214`（`pickImage`，被相机按钮和复合指令自动拉相册 `Ev.REQUEST_IMAGE` 调用）

```ts
DocImporter.importTextDocs().then((msg: string) => { ... });   // ← 没有 .catch
```

- 模拟器若系统文件选择器/相册选择器 UI 被裁剪或异常，`picker.select()` 的 Promise 会 **reject**；
  没有 catch 就意味着**按钮点击后界面毫无反馈**——这正是"不能处理文档"最直观的症状。
- `importTextDocs` 内部对单文件读取失败也只是计入 `skipped`（`DocImporter.ets:37-40`），
  最终提示「跳过 N 个」但不说明原因。

**验证**：点按钮后看 hilog 是否有未捕获异常（`ETS`/`Ace` 域的 unhandled rejection），
或临时在 DevEco 的 FaultLog 里查看。

---

### 🟡 P2：图片 >4MB 被静默丢弃，OCR 失败后的视觉降级链路「无图可发」

**位置：`entry/src/main/ets/core/ChatService.ets:645-666`（`fileToDataUrl`）**

```ts
if (stat.size > 4 * 1024 * 1024) {
  return null; // >4MB 跳过   ← 只 Log.warn，UI 无提示
}
```

- `send()` 中 `imageDataUrls` 为空时**不做任何提示**（`ChatService.ets:132-138`）。
- 链路 C 中 OCR 失败后走视觉 LLM 降级（`ChatService.ets:341` `runSingle(null, rawText, imageDataUrls, ...)`），
  若图片因 >4MB 被丢弃，模型收到的是**纯文本**「看一下这个文档，帮我总结重点」——
  模拟器上拍照/截图很容易超过 4MB，表现为模型说"请上传图片"或瞎编。

**验证**：hilog 找 `fileToDataUrl failed:`；或检查所选照片大小。

---

### 🟡 P3：DocumentViewPicker 在模拟器上的可用性存疑

**位置：`entry/src/main/ets/knowledge/DocImporter.ets:16-24`（`importTextDocs`）**

- 模拟器若未内置完整文件管理应用，`docPicker.select(opts)` 可能抛错（叠加 P1 的静默）
  或返回空（提示「未选择文件」，易被误判为 bug）。
- `readUriText`（`DocImporter.ets:106-124`）对 picker 返回的 `file://docs/...` URI 直接
  `fs.openSync`：授权仅在选择会话内有效，正常情况下可行，但模拟器的 docs provider
  行为与真机有差异，失败时只计入 skipped（见 P1）。

**验证**：hilog 找 `import xxx failed:` 的具体 message。

---

### 🟡 P4：离线/端侧问答链路在模拟器上无兜底

**位置：`entry/src/main/ets/knowledge/KbService.ets:362-375`（`askStream`）→ `RagBridge.ets:272-281`（`localAnswer`）**

- 设置页若开了「离线模式」，`askStream` 直接走 `offlineAnswer` → `localChatModel`。
  端侧问答模型在模拟器上**必然不可用**，`localAnswer` 抛错后 `offlineAnswer` **没有降级**，
  异常一路冒泡：`kb_ask` 工具（`KbService.ets:471-485`）和复合指令 `kb_ask` 子任务
  （`ChatService.ets:374-394`）都没有 try/catch 接住它。
- 非离线模式下 `rag.createRagSession` 在模拟器不可用已有防护（`RagBridge.kitAvailable`），
  会自动降级到「本地检索 + 云端 LLM」，此段是安全的。

**验证**：设置里确认「离线模式」开关；hilog 找 `端侧模型错误` / `端侧问答模型不可用`。

## 三、快速定位操作步骤

1. 真机对比：同一操作在真机上正常 → 基本可锁定为模拟器能力裁剪（P0/P3/P4）。
2. 抓日志：
   ```bash
   hdc shell hilog | grep OpenCompanion
   ```
   按症状对照下表：

   | 模拟器上的现象 | 对应出错点 |
   |---|---|
   | 点「导入文档/拍照识字」完全没反应 | **P1**（picker reject 无 catch） |
   | 提示「未能从图片中识别出文字」 | **P0**（OCR 模块缺失） |
   | 提示「已导入 0 个文档，跳过 N 个」 | **P3**（picker/读取失败，原因被吞） |
   | 拍照总结时模型说"没看到图片"或答非所问 | **P0 + P2**（OCR 失败 + 图片未传给视觉模型） |
   | 开了离线模式后知识库问答直接报错/中断 | **P4** |

3. 一行命令确认 OCR 能力（可临时加在 `EntryAbility.onCreate` 验证后删除）：
   ```ts
   Log.info(`ocr syscap = ${canIUse('SystemCapability.AI.Vision.OCR')}`);
   ```

## 四、结论

最可能的组合是 **P0（模拟器裁剪 OCR 原生模块）+ P1（错误被静默吞掉）**：
能力本身缺失是模拟器环境限制，但代码把失败吞得太干净，导致界面上表现为
"没反应 / 识别不出 / 答非所问"，看起来像是"完全不能处理文档"。
P2、P4 是会放大问题的次要因素。修复方向（待确认后再动代码）：

1. OCR 入口加 `canIUse` 检测，不可用时给出明确文案而不是静默失败；
2. 页面层所有 picker 调用补 `.catch` / try-catch，把异常变成用户可见的提示；
3. 图片超限、图片丢失时在消息轨迹中显式说明；
4. `offlineAnswer` 增加降级（端侧模型不可用时回落本地检索原文）。
